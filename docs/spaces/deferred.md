# Deferred work and decisions

Things we chose not to do yet, or decided on purpose, so they aren't
rediscovered as bugs. Add a row when you defer something; remove it when it's
done or no longer applies. `status.md` tracks what's in progress.

## Decisions

| Decision | Why | Where |
| --- | --- | --- |
| Per-space isolation ships as an advanced setting, off by default, that warns notifications, push and cookie extensions don't work in the space (Gate 2, 2026-10-25) | Logins, popups, downloads, uBlock and extension scripts work per space; push and `chrome.cookies` don't. The click (E3) and DevTools (E13) checks passed by hand on 2026-10-28, once a link opened in a new window kept its space; passwords don't apply to Helium | `spikes/space-isolation.md`, Gate 2 |
| No hook to allow notifications in an isolated space | It fixes notifications but not push, and per-space profiles will fix both | `spikes/space-isolation.md`, Gate 2 |
| Partition isolation stays once per-space profiles exist, as a lighter option next to them | It keeps history, passwords and extensions shared while separating logins, which a profile can't. Arc has only profiles; this adds to Arc's behavior rather than changing it | `spec.md`, Feature 2 |
| A space with separate logins doesn't show the favorites, and its tab menu offers Pin but not "Add to Favorites". Activating a favorite there by other means, such as an extension, switches to the most recently used space that shows favorites | Favorites live in the profile's default storage, and a tab can only be in one. The user chose this over separate favorites now or showing them with the default logins (2026-10-27) | `SpaceController::IsTabInActiveSpace()`, `ShouldShowAddToFavorites()` |
| A tab that changes space, by any route, reloads in the new space's storage if it differs: moved, dropped, dragged to another window, grouped, split, unpinned from the favorites, or in a space whose separate logins are turned on or off, or that is removed. It keeps its place, group and history | One choke point, `SpaceController::SetTabSpace()`, catches every route. The move waits for a tab drag to end, since a dragged tab joins the space of every window it passes over | `SpaceController::MoveTabsToTheirPartitions()` |
| Turning a space's separate logins off keeps its storage, so turning them on again signs it back in; removing the space deletes it | A checkbox should be undoable. The startup storage cleanup keeps the storage of every existing space | `GetSpaceStoragePaths()`, `ClearSpaceStorage()` |
| A space with separate logins keeps session cookies across restarts, as the default storage does | Chromium drops them for every partition but the main one, which signed users out at every restart (spike E4) | `profile_network_context_service.cc` hook |
| Separate logins is a checkbox in the Edit space bubble, with a description of what doesn't work in such a space | Gate 2's "advanced setting with a warning" | `ShowSpaceSettingsBubble()` |
| The default space can have separate logins too | Nothing in the model stops it. Favorites then show in no space with separate logins, the default space included | `SpaceController::IsSpaceIsolated()` |
| Favorites belong to the profile, as in Arc, not to a space: a favorite is a pinned tab stored with a reserved id, `GetFavoritesId()`, in place of a space id, and shows in every space without separate logins. Every space has its own pinned tabs, the default space too | The user chose Arc's model (2026-10-26). In Arc, favorites belong to the profile and show in every space using it, and pinned tabs to one space. Replaces "a pinned tab of the default space is a favorite", which left the default space without pinned tabs of its own | `SpaceController::IsFavorite()`, `spec.md` |
| Favorites saved under the old rule come back as pinned tabs of the default space; they aren't migrated | The flag is off by default and unreleased, so only test profiles have any. "Add to Favorites" makes them favorites again | `SpaceController::GetSpaceOfTab()` |
| A favorite moved with "Move to Space" or dropped on a space's icon becomes a pinned tab of that space | It stays pinned; only its space changes | `SpaceController::MoveTabToSpace()` |
| Duplicating a favorite makes a space-pinned tab of the active space | Duplicates are new tabs, and new tabs join the active space | `SpaceController::OnTabStripModelChanged()` |
| New tabs always join the active space, never their opener's | Simpler, and an opener in another space is rare (only a hidden tab opening a window) | `SpaceController::OnTabStripModelChanged()` |
| A window opened from a tab, by "Open Link in New Window" or a Shift-click, starts in that tab's space, so its first tab keeps the space's logins. From a favorite, it starts in the space the favorite shows in | The new window used to start in the default space and open the link with the default logins (hands-on E3, 2026-10-28). Other new windows, such as Cmd+N, still start in the default space | `spaces::StartNewWindowInSourceSpace()`, hook in `Navigate()` |
| The active space is not saved; it follows the active tab, or, with a favorite active after a restart, the most recently active other tab | Tabs' last-active times are already in the session, so no window extra data or session restore hooks are needed. A tab opened in the background after the last-active one can win after a restart, which is nearly always the same space | `SpaceController::GetSpaceForActiveTab()` |
| Closing a space's last tab opens a New Tab page there, rather than moving to another space | Arc keeps you in the space; focus mode exits instead, which is the behavior we don't want | `SpaceController::WillCloseTabs()` |
| Switching spaces is instant in the horizontal strip, not animated | Animating, as focus mode does, shows the old space's tabs shrinking away | `BrowserTabStripController::InitFromModel()` hook |
| A tab moved to another space leaves its tab group, and a tab in a split view takes the other tab with it, to the end of the new space's tabs | Groups and splits stay within one space, so a group's visibility follows its first tab | `SpaceController::MoveTabToSpace()` |
| Each space's tabs stay together in the tab strip, pinned and unpinned apart, with favorites before any space's pinned tabs | The user's rule from the planning doc. Favorites first matches Arc's favorites grid and the sidebar planned for step 4 | `space_order.h` |
| Moves stay inside the tab's own space, extensions' included; a tab put among another space's tabs goes to the nearest end of its own | Changing space is always explicit (step 4's menu and switcher). Clamping keeps an extension that sorts tabs from mixing spaces. Hidden spaces have no visible edge to drag across | `SpaceController::ConstrainMoveIndex()` |
| If the order still breaks, `SpaceController` fixes it in a posted task, logs a warning, and counts it | Protects users from a hook we missed; `chrome://spaces-internals` shows the count and the smoke test fails on it | `SpaceController::FixOrderIfInvalid()` |
| A tab moved or dragged into another window joins the space that window shows, as in Arc. Favorites stay favorites, and a tab torn off into a new window keeps its space | It lands where it was dropped | `SpaceController::WillInsertTabs()` |
| Unpinning a favorite, or grouping it (which unpins it), moves it to the active space, as in Arc | Replaces the step 3a behavior, where it became a default-space tab and the window switched to the default space | `SpaceController::WillSetTabPinned()` |
| A tab added to a tab group joins the group's space | Keeps groups in one space, whether the tab came from the menu, a drag or an extension | `SpaceController::TabGroupedStateChanged()` |
| A split view's tabs take the space of the tab it is made from, the active one: a favorite split with an active space's tab joins that space, and a tab split with an active favorite becomes a favorite | Keeps a split in one space, and the active tab where it is | `SpaceController::WillSplitTabs()` |
| While a tab drag goes on, a tab that comes back to the window the drag started in, or is put back by cancelling, gets back the space it had there | Chromium attaches a dragged tab to every window it passes over, so hovering over another window would otherwise move it to that window's space for good | `WillDragTabs()` in `space_tab_helper.h` |
| A window holding only favorites takes the space of the first other tab moved in | "Move tabs to new window" with a favorite selected moves the favorite first | `SpaceController::WillInsertTabs()` |
| Moving a space's last tab to another window doesn't open a New Tab page in it | During a drag the tab leaves the window as soon as it leaves the strip; a New Tab page opened then would stay behind if the tab came back | `SpaceController` (no hook on detach) |
| Removing a space puts its tabs with the default space's, its pinned tabs too | They now belong to the default space. Arc deletes a space's tabs with it | `SpaceController::OnSpacesChanged()` |
| Cmd+Opt+Left/Right switch spaces instead of tabs while the flag is on, and Ctrl+1..9 select a space, as in Arc | Arc's keys. Tabs still switch with Ctrl+Tab and Cmd+Shift+[ ]. The spec's Ctrl+Opt+1..9 would clash with VoiceOver's modifier; Ctrl+1..9 clash with Mission Control's "Switch to Desktop N" only when the user turns those on. All are rebindable on Helium's shortcuts page | `global_keyboard_shortcuts_mac.mm` hook, `spec.md` |
| Ctrl+1..9 aren't reserved, so a web page can still take them; Cmd+Opt+Left/Right are, as Chromium reserves next/previous tab | Chromium doesn't reserve Cmd+1..9 either. In a window without spaces (incognito, guest, apps), Cmd+Opt+Left/Right switch tabs as before and Ctrl+1..9 do nothing | `browser_command_controller.cc` hook |
| Next and previous space wrap around at the ends | As tab switching does. Arc's behavior at the ends is unverified | `GetAdjacentSpaceId()` |
| Every tab that isn't a favorite gets Pin and "Add to Favorites"; a favorite's Unpin reads "Remove from Favorites" | Pin keeps a tab in its space, and "Add to Favorites" shows it in every space, as Arc's "Move To > Favorites" does | `GetPinMenuItemStringId()`, `ShouldShowAddToFavorites()` |
| "Add to Favorites" pins the tabs first, then makes them favorites | In that order an active tab stays active and the window keeps its space | `TabStripModel::ExecuteContextMenuCommand()` hook |
| "Move to Space" and a drop on a space's icon keep the window in its space; a moved active tab is replaced by another of the space | Matches `MoveTabToSpace()` from step 3c; Arc moves the tab without following it | `SpaceController::MoveTabToSpace()` |
| A group dragged by its header onto a space's icon moves as a group; dragged tabs move one by one and leave their groups | A header drag means the group | `SpaceController::MoveDroppedTabsToSpace()` |
| "+" adds "Space N" in the next color of the tab group palette, switches to it and opens its settings bubble | Arc asks for a name when a space is made | `SpaceSwitcherView::AddSpace()` |
| Deleting a space doesn't ask for confirmation | Its tabs aren't closed; they move to the default space | `SpaceSwitcherView` |
| In the collapsed sidebar only the active space's icon shows, and clicking it lists the spaces in a menu | There is no room for a row at 42 px | `SpaceSwitcherView::Layout()` |
| Icons shrink to dots when they don't fit, and to the active one alone if even dots don't, which then opens the spaces menu as in the collapsed sidebar | As Arc does with many spaces; the menu keeps every space reachable | `SpaceSwitcherView::Layout()` |
| Any change of tab visibility closes a showing hover card at once, not only a space switch | A tab moved to another space from the menu also disappears; no card is usually showing then | `HideHoverCardImmediately()` hooks |
| No swipe to switch spaces in Classic, Compact and Dynamic; they'll switch with a button or menu, plus the keyboard shortcuts | A horizontal swipe over a horizontal tab strip is easily confused with scrolling its tabs. The shortcuts already cover switching there | `spec.md`; the user, 2026-10-24 |
| The smoke and screenshot scripts disable `MacDisclaimGpuTccResponsibility`, so the GPU process shares the terminal's privacy permissions | With `build/` out of `~/Documents` it isn't needed, but it keeps an unattended run (screen locked, agents) from hanging on a privacy prompt if the build ever lands in a protected folder again. Release Helium is launched by launchd, where Chromium doesn't disclaim at all, so the tests' process model matches it | `devutils/spaces_smoke.mjs` `launch()`, `development.md` |
| Dynamic's new-tab button is in the toolbar | Helium's design (`ShouldShowNewTabButton()`), not ours | Helium |
